Things to make Claude Code do.

Numbered folders, and the list keeps growing. Each one holds a realistic mess, one prompt to paste, and a README saying what should come out the other side. Open a folder, paste the prompt, then look in finished/run-01/.

The loop

Three steps, repeated for every folder.

There is nothing to configure and nothing to read first. Every exercise is the same loop, and most need nothing installed at all.

1 · Open the folder

cd 07-copy-your-writing-style then claude. Open Claude Code inside the exercise folder, not at the top level — every prompt uses relative paths like raw/data.

2 · Paste the one prompt

Each exercise has exactly one. It is on that exercise's slide with a Copy button, and in the folder's README.md if you would rather read than click.

3 · Check what landed

Everything goes to finished/run-01/. The slide and the README both list what you should see, including real numbers you can check the answer against.

raw/ is never modified, and your second attempt goes in run-02/ — not over the top of your first.
Why that matters: comparing run-01 with run-02 after you have improved a prompt is the lesson — and it is invisible if the second run overwrites the first. It also means re-running can never destroy anything, so you will not hesitate to try a worse prompt on purpose.
What it costs to start: most of the list need nothing but Claude Code. The rest name a single install: Python (12, 18, 21), Node (13, 15), ffmpeg + Whisper (14), Git (16). Four need something you own: Docker (19), a system of yours (20), your own scheduler (22), a hosting account (23). Every command is in SETUP.md, and none of it is mine — every exercise runs on your machine, under your accounts.

The list, at a glance

What each exercise gives you.

Four things per card: the number, what Claude does, the file you end up with, and what it costs to start. Work in order the first time. The order is ambition, not setup cost, which is why some late ones need nothing installed.

Every folder holds the same three things: README.md (the situation, the prompt, what to expect, what it means), raw/ (supplied material, never modified) and finished/ (your runs). Every install command is in SETUP.md, and each slide that needs one carries it.

Where this leaves you

Knowing what to ask for is the bottleneck now.

Worth being explicit about what changed, because the individual exercises undersell it.

What you can do that you couldn't three hours ago

Hand off tedious work in bulk (01, 03, 17). Audit things nobody has checked in years (02, 05, 17). Answer a question that was invisible behind a chore (04). Produce artefacts in the formats real people demand (06, 08, 12).

Write down how you write (07), how your team works (10) and how you do a recurring job (11), so none of it needs re-explaining. Read a browser (13) and your own systems (20), make video (14, 15), break things safely (16), stand up real infrastructure (19), schedule work you never watch (22), and publish (23).

What actually changed

Not that any single task got faster. That expertise stopped being the constraint — and you're the one who knows which questions matter in your own work.

Go and point this at something real. Start with the most boring recurring thing you do; that's where it pays first.

Before you put the kit down: exercise 22 registered a scheduled task and exercise 23 may have deployed a site. Ask Claude to list everything it created on your machine, and give you the commands to remove it.
